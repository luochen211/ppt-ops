# Design Mode

Read the content-review report matching the accepted Outline, if one exists, using `content-review.md`. Carry its audience job, on-slide/spoken split, and unresolved evidence boundaries into design. A report for an older revision is stale; do not apply its wording automatically. Design does not restart content research for a purely visual request.

Use the accepted Outline, profile brand rules, user-accepted visual preferences when available, semantic template catalog, `visual-quality.md`, and `visual-assets.md`. Proposed, rejected, removed, or superseded visual-preference candidates are evidence only and must not steer a later project. Define Theme tokens, opening job, page rhythm, page-template choices, asset needs, and density budgets without changing facts. Apply the declared delivery mode: live talks and pitches need tighter visible-copy budgets than leave-behinds; workshop interaction is declared only on pages where the audience actually acts. Record timing as an unrehearsed estimate unless rehearsal evidence exists, and keep speaker-note intent outside `screen_text`. Always create ImageGen briefs and slots for the canonical first and final page; for a one-page deck one accepted image may own both roles. Define each asset's semantic action before choosing a style preset. Exit with an accepted design direction and explicit boundary-image status. Load Source bodies only when a cited visual decision requires authorization.
