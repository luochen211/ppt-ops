# 《从毕业设计到持续接单》图形构思方向

状态：本轮已实施，待用户视觉反馈。用户已授权按整体审阅建议整理并继续部署。保持 23 页、四模块与原有青绿品牌体系。

设计真源为 design-direction.json；逐页内容见 pages.json；实施说明见 editorial-refresh.md。

## 视觉原则

一页一个主结论。真实截图负责解释具体业务页面；原生图解负责表达阶段、角色、范围和输入输出。截图不作为本次测试通过证据，教学示例明确标注。内容页使用浅薄荷背景、深绿大字、克制阴影；章节页保留原有深浅交替。全部标题和说明使用 HTML 文字，图片独立存储、可点击放大。

## 页面节奏

- 1–3：整体旅程、客户购买的结果、四段路线。
- 4–7：毕设业务起点、物流项目角色流转、可操作的 Demo。
- 8–12：表单提问、四项确认、分阶段交付、确认记录。
- 13–18：面对陌生技术的耐心、人机职责、连续执行、独立视频、具体变更判断。
- 19–23：第一单与下一单的两种路径、作品包、需求沟通行动、收尾。

## 逐页决策

| 页 | 标题 | 关系 | 阅读路径 | 设计理由 |
|---:|---|---|---|---|
| 1 | 从毕业设计到持续接单 | hero | brand → title → subtitle | 用起点式封面邀请观众进入完整旅程 |
| 2 | 客户要的，是业务真正跑起来 | comparison | 主结论 → 订单提交 → 团队处理 → 费用查询 | 正面呈现客户购买的三个业务结果，放大核心结论。 |
| 3 | 从毕业设计出发，走向第一单和下一单 | sequence | 第一单与信任 → 需求与项目 → AI 与交付 → 持续接单 | 用二乘二编号目录完整呈现用户确认的四个模块。 |
| 4 | 从毕设到第一单 | hero | 章节编号 → 从毕设到第一单 → 让客户相信你 | 用用户确认的主标题与副标题开启该模块。 |
| 5 | 最早，我从毕设项目起步 | hierarchy | 毕设起点 → 闲鱼获客 → 客单价 → 全包内容 | 以价格、获客渠道和全包内容简要介绍真实毕设起点，再进入企业物流案例，不扩展获客教程或答辩细节。 |
| 6 | 一张订单，串起三种角色 | sequence | 客户 → 操作员 → 财务 | 用角色与箭头解释业务流转，去掉重复的系统全图。 |
| 7 | 做企业商单，一定要有 Demo 能力 | process | Demo 观点 → 详情截图 → 试用流程 | 订单详情配具体试用动作，展示 Demo 如何帮助沟通。 |
| 8 | 从模糊需求到万元项目 | hero | 章节编号 → 从模糊需求到万元项目 → 把事情定义清楚 | 用用户确认的主标题与副标题开启该模块。 |
| 9 | 一个表单，先问清三件事 | process | 表单截图 → 谁来填 → 哪些必填 → 谁接着处理 | 放大真实表单，把需求问题控制为三项。 |
| 10 | 先确认四件事，再交给 AI 执行 | hierarchy | 四项确认 → 单箭头 → 任务书 → AI 执行 | 四张确认卡汇入任务书，仅保留一根指向 AI 任务输入的箭头；文字保持可编辑。 |
| 11 | 先说清每一阶段交什么 | sequence | 业务阶段 → 财务阶段 → 管理阶段 → 各阶段确认点 | 以交付内容和确认点为主图，避免截图挤占阶段信息。 |
| 12 | 每一阶段，都留一个确认点 | sequence | 开工前 → 过程中 → 交付时 | 明确三个沟通时机与各自应留存的记录。 |
| 13 | 从会用 AI 到能完成交付 | hero | 章节编号 → 从会用 AI 到能完成交付 → 人和 AI 如何分工 | 用用户确认的主标题与副标题开启该模块。 |
| 14 | 目标明确，陌生技术也能做出来 | process | 面对陌生技术 → 明确目标 → 耐心尝试 → 对照调整 | 以目标、尝试、调整的连续路径呈现面对陌生技术的耐心，承接已确认需求并引出人机分工。 |
| 15 | 人定方向，AI 完成执行 | comparison | 人负责判断 → 需求给 AI → AI 执行 → 结果返回人 | 人和 AI 的输入输出各自标注方向；三组职责用可投影字号呈现。 |
| 16 | 开发和测试，都交给 AI | process | 实现 → 操作测试 → 修复重测 → 整理结果 | 展示实现、测试、修复的连续执行关系，避免用静态项目图冒充测试录像。 |
| 17 | 手机端、多角色，Computer Use 来测 | hero | 演示主题 → 本地视频选择 → 独立视频画面 | 按用户回复保留独立演示页与本地文件选择，不伪造录制素材。 |
| 18 | 客户说“加一个选项”，先确认三件事 | process | 已有选项截图 → 新增理由 → 范围变化 → 预期结果 | 从真实下拉选项入口切入小需求，把人的取舍变成具体问题。 |
| 19 | 从一次交付到持续接单 | hero | 章节编号 → 从一次交付到持续接单 → 走向第一单和下一单 | 用用户确认的主标题与副标题开启该模块。 |
| 20 | 起点不同，都从已有成果开始 | comparison | 还没有商单 → 第一单行动 → 已经交付过项目 → 下一单行动 | 对照两种起点，各给出三项行动，让第四模块落到第一单和下一单。 |
| 21 | 用一个作品包，支撑下一次沟通 | hierarchy | 演示 → 截图 → 说明 → 需求沟通 | 让毕设与商单都能形成可展示的材料，服务具体需求沟通。 |
| 22 | 下一步：用作品开启一次具体沟通 | sequence | 选择对象 → 演示流程 → 询问具体问题 → 定义新项目 | 用三个连续动作把作品材料接到需求沟通，不虚构成交结果。 |
| 23 | 从能做出来，到值得被交给你。 | hero | 建立信任 → 明确需求与分工 → 走向第一单和下一单 | 收束四模块并落到接单行动。 |
