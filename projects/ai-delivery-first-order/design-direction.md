# 《从毕业设计到持续接单》图形构思方向

状态：本轮已实施，待用户视觉反馈。用户已授权按整体审阅建议整理并继续部署。保持 22 页、四模块与原有青绿品牌体系。

设计真源为 design-direction.json；逐页内容见 pages.json；实施说明见 editorial-refresh.md。

## 视觉原则

一页一个主结论。真实截图负责解释具体业务页面；原生图解负责表达阶段、角色、范围和输入输出。截图不作为本次测试通过证据，教学示例明确标注。内容页使用浅薄荷背景、深绿大字、克制阴影；章节页保留原有深浅交替。全部标题和说明使用 HTML 文字，图片独立存储、可点击放大。

## 页面节奏

- 1–3：整体旅程、客户购买的结果、四段路线。
- 4–7：闲鱼获客、角色流转、可操作的 Demo。
- 8–12：表单提问、四项确认、分阶段交付、确认记录。
- 13–17：人机职责、连续执行、独立视频、具体变更判断。
- 18–22：验收路径、作品包、三张截图的介绍顺序、收尾。

## 逐页决策

| 页 | 标题 | 关系 | 阅读路径 | 设计理由 |
|---:|---|---|---|---|
| 1 | 从毕业设计到持续接单 | hero | brand → title → subtitle | 用起点式封面邀请观众进入完整旅程 |
| 2 | 客户要的，是业务真正跑起来 | comparison | 主结论 → 订单提交 → 团队处理 → 费用查询 | 正面呈现客户购买的三个业务结果，放大核心结论。 |
| 3 | 沿着一单项目，走完四个环节 | sequence | 机会 → 需求 → 交付 → 作品 | 四个有编号的环节串起全篇，每步指向一个可带走的产物。 |
| 4 | 从毕设到第一单 | hero | act-number → act-title → act-outcome | 给第一段留出认知换气 |
| 5 | 这单物流项目，来自闲鱼 | process | 获客渠道 → 作品示例 → 沟通方法 | 渠道与真实作品分开表达，不把系统页面当作获客过程证据。 |
| 6 | 一张订单，串起三种角色 | sequence | 客户 → 操作员 → 财务 | 用角色与箭头解释业务流转，去掉重复的系统全图。 |
| 7 | 做企业商单，一定要有 Demo 能力 | process | Demo 观点 → 详情截图 → 试用流程 | 订单详情配具体试用动作，展示 Demo 如何帮助沟通。 |
| 8 | 把物流需求定义清楚 | hero | act-number → act-title → act-outcome | 从信任问题切换到需求定义 |
| 9 | 一个表单，先问清三件事 | process | 表单截图 → 谁来填 → 哪些必填 → 谁接着处理 | 放大真实表单，把需求问题控制为三项。 |
| 10 | 先确认四件事，再交给 AI 执行 | hierarchy | 四项确认 → 单箭头 → 任务书 → AI 执行 | 四张确认卡汇入任务书，仅保留一根指向 AI 任务输入的箭头；文字保持可编辑。 |
| 11 | 先说清每一阶段交什么 | sequence | 业务阶段 → 财务阶段 → 管理阶段 → 各阶段确认点 | 以交付内容和确认点为主图，避免截图挤占阶段信息。 |
| 12 | 每一阶段，都留一个确认点 | sequence | 开工前 → 过程中 → 交付时 | 明确三个沟通时机与各自应留存的记录。 |
| 13 | 从会用 AI到能完成交付 | hero | act-number → act-title → division-question | 进入全篇责任边界的核心章节 |
| 14 | 人定方向，AI 完成执行 | comparison | 人负责判断 → 需求给 AI → AI 执行 → 结果返回人 | 人和 AI 的输入输出各自标注方向；三组职责用可投影字号呈现。 |
| 15 | 开发和测试，都交给 AI | process | 实现 → 操作测试 → 修复重测 → 整理结果 | 展示实现、测试、修复的连续执行关系，避免用静态项目图冒充测试录像。 |
| 16 | 手机端、多角色，Computer Use 来测 | hero | 演示主题 → 本地视频选择 → 独立视频画面 | 按用户回复保留独立演示页与本地文件选择，不伪造录制素材。 |
| 17 | 客户说“加一个选项”，先确认三件事 | process | 已有选项截图 → 新增理由 → 范围变化 → 预期结果 | 从真实下拉选项入口切入小需求，把人的取舍变成具体问题。 |
| 18 | 从一次交付到持续接单 | hero | act-number → act-title → next-order | 把一次性交付转向持续信用 |
| 19 | 交付前，把一条业务流程走到底 | process | 保存入口 → 提交 → 查回 → 切角色核对 | 用保存入口与验收路径代替重复总结；截图与测试通过证据分开。 |
| 20 | 做完一单，留下一个作品包 | hierarchy | 演示 → 截图 → 说明 → 作品包 | 把抽象材料沉淀具体化为演示、截图、说明三个可整理的产物。 |
| 21 | 三张图，讲清这套系统怎么用 | sequence | 列表 → 表单 → 详情 → 介绍顺序 | 真实截图各自承担列表、表单、详情一种用途，形成项目介绍顺序。 |
| 22 | 从能做出来，到值得被交给你。 | hero | title → closing-sentence → negative-space | 最后留下值得被交付的信用判断 |
