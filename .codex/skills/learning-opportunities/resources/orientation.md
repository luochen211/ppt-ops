# Repo Orientation: career-ops

> Generated by orient. Re-run to update.

## One-line purpose

career-ops 把 Codex 等 AI 编码 CLI 变成一个本地优先、可更新且有人类确认门的求职操作系统，用结构化模式、确定性脚本和人类可读文件管理从职位发现到入职结果的完整流程。

## Primary language(s)

- JavaScript（主系统、CLI、扫描、跟踪、更新与验证）
- Markdown / YAML / TSV（Agent 模式、用户配置和业务真源）
- Go（可选终端 Dashboard）

## Pipeline / workflow stages

1. 单一 `career-ops` Skill 根据自然语言、URL 或显式 mode 选择工作流。
2. Router 只加载共享规则、用户 Profile、用户 Custom 和目标 Mode 所需上下文。
3. Mode 让 Agent 读取用户层真源并调用确定性 Node 脚本完成扫描、提取、编号、写入或生成。
4. 中间结果进入 `data/pipeline.md`、`reports/`、`batch/tracker-additions/` 等可审计文件。
5. 合并、锁、去重、状态枚举与验证脚本维护 `data/applications.md` 这一业务真源。
6. 人类审核后才允许申请、发送、确认事实或记录最终结果。
7. Updater 只替换系统层文件，并通过备份、差异、兼容检查与回滚保护用户层。

## Core concepts

**Router + Modes**: 一个公开 Skill 负责意图识别，`modes/*.md` 分担具体业务流程；只加载当前 Mode 的必要上下文。

**System Layer / User Layer**: 可更新的程序规则与不可覆盖的用户事实完全分开，边界写在 `DATA_CONTRACT.md` 并由 updater 测试强制执行。

**Files are canonical**: Markdown、YAML、TSV 和产物目录是永久真源；SQLite 只做可删除、可重建的查询索引。

**Agent judgment + deterministic writes**: Agent 负责理解与建议，Node 脚本负责锁、编号、状态变更、去重、原子写入和验证。

**Human-in-the-loop**: 外部材料永远是数据而不是指令；提交、发送、事实确认和高风险更新需要用户确认。

## Common gotchas

- 不要把用户定制写进 `modes/_shared.md`；事实和目标进入 `modes/_profile.md` / `config/profile.yml`，流程偏好进入 `modes/_custom.md`。
- 不要直接向 `data/applications.md` 添加新行；先写 tracker addition，再用 `merge-tracker.mjs` 合并，已有状态用 `set-status.mjs` 修改。
- 不要把 SQLite 当真源，也不要为了“整洁”移动根目录脚本；大量更新清单、插件和用户肌肉记忆依赖稳定路径。

2. 打开 `ARCHITECTURE.md`，读 “The two layers” 和 “Files are canonical”。合上文件后，说明一次系统升级为何不会覆盖个人数据，以及 SQLite 在系统中为什么只能是派生层。
